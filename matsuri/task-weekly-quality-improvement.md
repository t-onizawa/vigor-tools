# VIGOR MATSURI — 週次品質改善タスク

Codex Scheduled Task用の実行指示書。Codex側のプロンプトは本ファイルを
読み込んで指示通りに実行する形にする。基準・運用ルールの変更は本ファイル
のみを更新し、Codex側のプロンプト自体は書き換えない。

---

## 実行環境の強制確認

実行開始時に必ず `git fetch origin` を行い、`git rev-parse --show-toplevel`、
`git rev-parse --git-dir`、`git status --short --branch` を確認する。

通常作業ツリー、またはローカルmainの未push・未commit状態を参照している
場合は、そこで作業・commit・pushしてはならない。origin/mainを直接基点
として、その実行専用の新しいGit worktreeを作成し、以降の全作業を専用
worktree内の matsuri/ だけで行う。ローカルmainをworktree作成元に
使わない。

専用worktree作成後、HEADが作成時点のorigin/mainと一致し、作業ツリーが
cleanであることを確認する。確認できなければ変更せず停止して報告する。

反映直前にも `git fetch origin` を行い、作業開始時からorigin/mainが
更新されていた場合は最新origin/mainを安全に取り込んで全検証を再実行
する。コンフリクトまたは検証失敗時はpushしない。

VIGOR MATSURIの週次品質改善を実施する。

実行開始時、リポジトリ内のBacklog.md・Roadmap.md・関連ドキュメントを
確認し、現在の運用方針・Phase・採用基準に従って作業する。

目的は「監査」ではなく、「安全に品質を改善すること」。

## 実行頻度

このタスクは平日毎日実行する。

以下を優先順位順に実施する。

## 1. データ品質を確認する（修正はしない）

以下に不整合がないか確認する。
（※週次データ整合性チェック・自動反映の専管領域のため、気づいても
本タスクでは修正しない）

- dates
- eventStatus
- links
- schema
- 表示崩れにつながるデータ不整合

不整合に気づいた場合は修正せず、完了報告に参考情報として記載するに
留める。

## 2. コンテンツ品質を確認する

現在の運用方針に従い、以下を品質改善対象とする。

- backgroundImage不足
- atmosphereMedia不足
- mapReference.lat/lng不足（mapReference自体は確定済みのもの）
- note不足
- その他、Backlog・Roadmapで品質改善対象となっている項目

## 3. 素材品質を改善する

backgroundImageを最優先とする。

### 対象選定

0. 【最優先・2026-09-16追加】今日の日付から起算して、開催まで
   概ね1〜2ヶ月以内（開催済みは対象外）の祭りのうち、backgroundImage・
   atmosphereMedia・mapReference.lat/lng（mapReference自体は確定済み
   のもの）のいずれかが欠けているものを、他の選定基準より優先して
   対象に含める。
   理由：開催が近づく祭りほど「祭り名＋年」でのピンポイント検索が
   増える時期であり、その直前に素材・位置情報を充実させておくことが
   実際の検索流入に直結する（Search Consoleの実測で、直近の上位
   クエリ・上位ページが軒並み1〜2ヶ月以内開催の祭りだったことから
   確認済み）。
   直近7日以内に本タスクで確認済み（採用・不採用いずれの結果でも）の
   祭りは、この枠から除外する（research/{slug}.mdの記録で確認する。
   2026-09-19追加：この除外ルールが無かったため、ほぼ同じ候補を毎日
   ゼロ件のまま再確認し続け、下記1〜4の通常選定に調査枠が一切
   回らない状態が続いていた）。
   除外後もなお該当件数が少ない（母数が少ない月もある）場合は、無理に
   20件に広げず、該当する全件を調査したうえで残りの調査枠は必ず
   下記1〜4の通常選定に充てる（0番の候補が20件に満たない限り、
   1〜4番の調査を0件のまま終えてはならない）。
1. 一度も本タスクで調査履歴がない「backgroundImage null かつ
   atmosphereMedia 空配列」の祭りを最優先とする。「直近追加された
   祭り」に限定せず、地域・追加時期を問わずfestivals/配下全体から
   選ぶ。
2. 該当がなければ、前回調査から4週間以上経過した「両方なし」祭りを
   再調査対象とする。
3. 直近4週間以内に本タスクで不採用判定済みの祭りは対象から除外する
   （research/{slug}.mdの記録で確認する）。
4. 上記1〜2に該当する「両方なし」祭りが見つからない場合は、片方だけ
   欠けている祭りを対象とする。backgroundImageが最優先方針のため、
   backgroundImageのみ欠けている祭り→atmosphereMediaのみ欠けている
   祭り、の順に対象とする。

1回の実行につき原則20件を調査する。対象選定ロジックに従って候補が
十分に存在する場合、20件に満たない時点で調査を打ち切ってはならない。
20件未満で終了するのは、候補枯渇・直接確認不能など正当な理由がある
場合に限り、その理由と実際に確認できた対象候補数を完了報告に明記
する。

判断基準は`atmosphere-media-guide.md`の既存基準（7節＝backgroundImage、
1〜6節＝atmosphereMedia、8節＝mapReference.lat/lng）をそのまま適用し、
基準を緩めない。検索結果の要約・スニペットだけで投稿者・内容を確定
させず、必ず動画ページ・画像を直接開いて確認する。

atmosphereMediaもbackgroundImageと同様に新規探索の対象とする
（週末バナー・一覧カードの表示にatmosphereMediaのサムネイルを直接
利用するようになったため、優先度をbackgroundImageと同等に引き上げた）。
ただしbackgroundImageは詳細ページヒーローにも使われるため、調査の
主軸は引き続きbackgroundImageとし、atmosphereMediaはこれと並行して
同じ調査対象祭りの中で探索する。

mapReferenceが確定済み（label・queryがある）でlat/lngのみnullの祭り
についても、`atmosphere-media-guide.md` 8節の基準に従い座標を確認
できれば記録する。mapReference自体が`null`の祭りへの新規調査はこの
基準の対象外とする。

research/{slug}.mdの記録文言が、画像・動画の実際の内容と一致して
いることを確認する（不一致がある場合は文言を修正するか、一致する
まで採用しない）。

品質基準を満たした素材は、その回ですべて反映する。

反映件数に上限は設けない。

backgroundImageのみ、atmosphereMediaのみ、mapReference.lat/lngのみ、
複数同時、いずれの反映も可とする。

品質基準を満たさない素材は反映しない。

## 4. 自動反映

以下のみ自動反映対象とする。

- backgroundImage追加
- atmosphereMedia追加
- mapReference.lat/lng追加
- 軽微なnote修正
- 軽微な品質改善

以下は自動変更しない。

- highlightComment
- SEO文言
- タイトル
- 説明文
- 体験タグ
- 検索意図に影響する文章
- 大きなUI変更
- 新機能追加

判断に迷うものは変更せず、レビュー候補として報告する。

## 5. テスト

変更後は既存運用で定められているテストを実施する。

- `node --check`
- `git diff --check`
- backgroundImage採用時：詳細ページヒーローを390×844と1440×900で
  確認し、文字重なり・アスペクト比崩れがないこと
- atmosphereMedia採用時：詳細ページのギャラリー表示・クリック展開が
  正常に動作すること
- console errorがないこと、横スクロールが発生しないこと

`node --check`、`git diff --check`、または今回の変更によって生じた
機能不具合がある場合は反映せず停止する。

既存の表示不具合や、今回の変更が原因ではない文字重なり・アスペクト比
崩れ・横スクロール・console errorを発見した場合は、完了報告に対象
ページ、再現条件、症状を記載するが、それだけを理由に素材調査・許可
範囲内の変更・commit・main反映を停止しない。今回の変更が既存不具合を
悪化させていないことは確認する。表示不具合そのものは本タスクで修正
せず、後で人間が対応できるよう報告する。

## 6. 反映

問題がなければ既存運用ルールに従いmainへ反映する。

## 7. レポート

最後に以下を報告する。

- 調査件数（20件未満の場合は理由と実際に確認できた対象候補数を明記）
- うち「開催が近づいている祭り」枠（対象選定0番）の調査件数・対象
  祭り名・反映結果（該当なしなら「該当なし（0件）」と明記）
- うち通常選定（対象選定1〜4番）へ回した調査件数・対象祭り名・反映
  結果（2026-09-19追加。0番だけで20件に達し1〜4番の調査が0件になった
  場合は、その旨と0番の候補が本当に20件以上あったことを明記する）
- 反映件数
- 画像（backgroundImage）追加：あり／なし、追加件数、対象の祭り名・
  slug。追加がなければ「なし（0件）」と明記する
- 動画（atmosphereMedia）追加：あり／なし、追加件数、対象の祭り名・
  slug。追加がなければ「なし（0件）」と明記する
- 位置情報（mapReference.lat/lng）追加：あり／なし、追加件数、対象の
  祭り名・slug。追加がなければ「なし（0件）」と明記する
- 反映後のbackgroundImage未設定・atmosphereMedia未設定・両方なし・
  mapReference.lat/lng未設定の件数（母数含む）
- 整合性チェック領域で気づいた参考情報（修正はしていない）
- 表示確認で見つけた既存不具合（対象ページ・再現条件・症状。なければ
  「なし」と明記）
- note修正件数
- 見送り件数と理由
- commit hash
- 次回改善候補

反映件数が15件を超えた場合は、その旨を完了報告へ明記し、次回実行前に
PMレビュー対象とする（反映自体は止めない）。

既存の「週次データ整合性チェック・自動反映」と責務を重複させず、
こちらは品質改善を担当する。
