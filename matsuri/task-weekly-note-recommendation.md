# VIGOR MATSURI — 週次「今週のおすすめ祭り」note記事タスク

Codex Scheduled Task用の実行指示書。Codex側のプロンプトは本ファイルを
読み込んで指示通りに実行する形にする。基準・運用ルールの変更は本ファイル
のみを更新し、Codex側のプロンプト自体は書き換えない。

---

VIGOR MATSURIの「今週のおすすめ祭り」note記事を作成・公開する。

## 目的

開催が近い祭りを1つ選び、短い紹介記事を書き、VIGOR MATSURIの該当
詳細ページへ自然な導線を作る。既存の「週次note下書き」タスク（一人称
エッセイ・その週に起きた活動から選ぶ）とは選定ロジック・文体が異なる
別タスクであり、役割を混同しない。

**このタスクに限り、Founderの明示的な許可によりnoteへの自動公開が
許されている**（AGENTS.md「note自動公開の例外」参照）。他のnote関連
タスクにはこの許可は適用されない。

## 対象祭りの選定ロジック

1. `matsuri/festivals/`配下の全`data.js`を確認する
2. 以下をすべて満たす祭りを候補とする：
   - `eventStatus`が`confirmed`または`scheduled_pending_official`
   - 2026年の開催日が実行日から30日以内
3. 以下は候補から除外する：
   - 過去に本タスクが紹介済みの祭り（note上の公開済み記事一覧を
     確認し、既出のslugを除外する）
   - note上で既に個人エッセイ等、独立した記事で大きく扱われている祭り
4. 候補が複数ある場合は、以下の優先順位で選ぶ（2026-10-06改訂）：
   0. **`constantInfo.notableDesignation`が設定されている祭り（UNESCO
      無形文化遺産・国指定重要無形民俗文化財・自治体公式が明記する
      「〇〇三大祭り」等、一次情報で確認済みの格付けがある祭り）が
      候補に含まれる場合は、それらの中から選ぶ（設定されていない
      候補は除外して検討する）。該当が1件もない場合は通常どおり
      全候補から選ぶ。**
      理由：有名・著名な祭りほど検索需要・読者の関心が見込め、note
      記事としての価値が高い（2026-10-06、Founderの指摘を受けて追加。
      ただし「有名そう」という主観では判断しない。あくまで
      `notableDesignation`フィールドに一次情報で確認済みの値が入って
      いる祭りに限る）。このフィールドはまだ一部の祭りにしか設定
      されていないため、該当0件になることも多い（その場合は通常の
      選定へフォールバックする。該当候補が無いこと自体は不具合では
      ない）。
   1. **まだ開催されていない祭り（初日が実行日より後）を優先する。**
      既に開催中の祭り（初日は過ぎたが最終日はまだ先）は、たとえ
      最終日が近くても優先度を下げる。理由：この記事は「行く前に
      読んで計画を立ててもらう」ための事前案内であり、読者が記事を
      読んだ時点で祭りが2/3ほど終わっている（残り1日等）状態では
      案内としての実用性が低い（2026-10-06、まだ開催されていない
      佐原の大祭 秋祭り（10/9〜11開催予定）を差し置いて、記事公開
      時点で既に開催2日目・最終日が翌日に迫っていた松山秋祭り
      （10/5〜7開催）が選ばれた事例から判明。開催済みかどうかを
      区別せず単純な日付の近さだけで選んでいたことが原因）
   2. 上記1の条件で複数が残る場合は、初日が最も近いものを選ぶ
   3. 上記1に該当する「まだ開催されていない」候補が1件もない場合に
      限り、既に開催中の祭りの中から最終日が最も先（残り日数が
      多い）ものを選ぶ
5. 候補が0件の場合は、記事を作らず完了報告のみ行う（該当祭りなしの
   旨と、次回以降の候補になりそうな祭りがあればメモを残す）

## 実行内容

1. 選んだ祭りと選定理由を短く示す
2. `matsuri/festivals/{slug}/data.js`と`matsuri/research/{slug}.md`の
   一次情報を確認する
3. タイトル案を3案作り、最有力を1つ選ぶ
4. 800〜1,200字程度の紹介文を書く（何が見どころか、いつ・どこで
   開催か、行く前に確認したいことを簡潔に伝える。既存の週次noteタスク
   のような一人称の起承転結エッセイにはしない）。`notableDesignation`
   が設定されている場合は、その内容（指定名・指定年等、確認できた
   範囲）を本文に含める（2026-10-06追加。読者の関心を引く材料として
   有効なため）
5. ハッシュタグ候補を3〜5個付ける
6. 件数・日付・固有名詞は`data.js`・`research/{slug}.md`で確認できた
   ものだけを使う。確認できないことは推測で埋めない
7. 記事末尾に、VIGOR MATSURIの該当詳細ページへのリンクを1つだけ置く。
   URLは以下の形式でUTMを付ける（`{slug}`は対象祭りのslugに置き換える）：
   `https://vigorlab.net/matsuri/festivals/{slug}/?utm_source=note&utm_medium=article&utm_campaign=weekly-pick-{slug}`
8. 上記リンクの直後に「他にもこんな祭りが近く開催されます」として、
   メインで紹介した祭り以外から2件を軽く添える（2026-09-30追加。
   詳細は下記「他の祭りの軽い紹介（2026-09-30追加）」を参照）
9. noteのログイン済みブラウザセッションを使い、採用タイトル・本文・
   ハッシュタグをnoteの新規記事編集画面へ入力し、**公開する**（下書き
   保存で止めず、公開操作まで実行する）
10. 公開後の記事URLを取得し、完了報告に記載する

## 他の祭りの軽い紹介（2026-09-30追加）

1件だけの紹介では特集として薄いため、メインの深掘り紹介に加えて、
他の祭り2件を名前・日付・リンクのみの軽い紹介で添える。

**選定ロジック：**
- 対象祭りの選定ロジック（上記）と同じ条件（`eventStatus`が
  `confirmed`または`scheduled_pending_official`、開催日が実行日から
  30日以内）を満たす祭りから、メインで選んだ祭りを除いて選ぶ。優先
  順位は上記「対象祭りの選定ロジック」4番と完全に同じ（`notableDesignation`
  設定済みの祭りがあればそこから優先、まだ開催されていない祭りを
  優先し、その中で初日が近い順。該当が無い場合はそれぞれフォール
  バックする）
- メインの祭りとは別の都道府県を優先する（同じ地域に偏らないように
  する）
- 開催日が完全に同じ祭りが複数あり優先順位を付けられない場合は、
  slug のアルファベット順など機械的に決まる基準で選んでよい（2026-10-06
  追加。どちらを選ぶべきかの判断材料が無い場合に悩まないための規定）
- こちらは軽い紹介のみのため、過去にメインとして紹介済みの祭りの
  重複チェックは不要（メイン選定ロジックの除外対象とは別に扱う）
- 条件を満たす祭りが1件しかない場合は1件のみ、0件の場合はこの節
  自体を出力しない（無理に埋めない）

**内容：** 祭り名・開催日・開催地（都道府県・市区町村）・リンクのみ。
説明文・見どころ等の追加の調査・執筆は行わない（リサーチ負荷を増やさ
ないことが目的のため）。

**形式：**
```
他にもこんな祭りが近く開催されます。

- {祭り名}（{開催日} {都道府県}{市区町村}）
  {リンク}
- {祭り名}（{開催日} {都道府県}{市区町村}）
  {リンク}
```

**リンク形式：** メインと区別できるよう、UTMの`utm_campaign`に`-sub`を
付ける（`{slug}`は対象祭りのslugに置き換える）：
`https://vigorlab.net/matsuri/festivals/{slug}/?utm_source=note&utm_medium=article&utm_campaign=weekly-pick-sub-{slug}`

## 毎回、作業開始時に必ず確認すること

- `NoteStyleGuide.md`（リポジトリルート）
- note上の公開済み記事・下書き一覧（重複確認）
- 対象祭りの`data.js`・`research/{slug}.md`

## 文体規約（NoteStyleGuide.mdに従う。特に以下を厳守）

- です・ます調で統一する
- 一人称「僕」は要所だけに使う
- 短い段落と多めの改行で読みやすくする
- 煽らない、成功や魅力を誇張しない
- 確認できた数字・日付・固有名詞を入れる。確認できないことは書かない
- 読者が行く前に確認したいことを1つ、具体的に入れる

## リポジトリ内の保存規約

このタスクはリポジトリへの下書きファイルを作成しない（note上で直接
公開まで完結するため）。リポジトリへの変更は発生しない（下記の
SNS投稿下書きは完了報告内のテキストとして出力するのみで、これも
リポジトリへの変更にはあたらない）。

## SNS（X）投稿下書き（2026-09-16追加）

**今回の実行で記事を公開できなかった場合（候補0件の場合）は、この節
自体を出力しない。** 無理に文面を作らない。

記事を公開できた場合のみ、完了報告の一番最後に、以下の形式でX投稿用
の下書きをそのまま追記する（Founderがコピペしてそのまま手動投稿する
運用のため、完成した投稿文としてそのまま使える状態で出力すること）。

```
【今週のおすすめ祭り】
「{祭り名}」を紹介する記事を公開しました。

{2026年の開催日} {開催地（都道府県・市区町村）}
{公開後のnote記事URL}

他にもこんな祭りが近く開催されます。
「{サブ祭り名1}」（{サブ1開催日} {サブ1開催地}）
{サブ1のMATSURIリンク}
「{サブ祭り名2}」（{サブ2開催日} {サブ2開催地}）
{サブ2のMATSURIリンク}

#祭り #山車 #神輿
```

（2026-09-30追加：「他にもこんな祭りが近く開催されます」以降は、本文
に添えた軽い紹介2件と対応させる。サブ祭りが1件しかない場合はその1件
のみ記載し、0件の場合はこのブロック自体を省く。サブ祭りのリンクURLは
以下の形式でUTMを付ける（`{slug}`は対象祭りのslugに置き換える）：
`https://vigorlab.net/matsuri/festivals/{slug}/?utm_source=x&utm_medium=social&utm_campaign=weekly-pick-sub-{slug}`
メインの祭りのリンクはnote記事URLのみとする方針を維持し、メイン祭り
自体のMATSURIリンクをX投稿へ重複して貼らない）

ルール：

- リンクはnote記事のURLのみを置く（VIGOR MATSURIの詳細ページ
  リンクは記事本文側に既にあるため、X投稿では二重に貼らない）
- note記事URLにUTMパラメータは付けない（note.com側の解析で活用
  できる保証がなく、リンクが煩雑になるだけのため）
- 開催日・開催地は`data.js`で確認できた値をそのまま使う（推測しない）
- この下書きはコピペしてそのまま使える完成形として出力し、
  「以下のような文面はいかがでしょうか」のような前置きは付けない

## 禁止事項

- 一人称エッセイ形式への逸脱（それは既存の週次noteタスクの役割）
- 過去に紹介済みの祭りを再度紹介すること
- 一次情報にない数字・日付・固有名詞の記載
- force push、`git reset --hard`、履歴の書き換え
- 関係のないファイルのcommit・push

## 完了報告に必ず含めること

- 選んだ祭りと選定理由（該当祭りなしの場合はその旨と次回候補メモ）
- 軽い紹介で添えた2件（該当が2件未満の場合は実際の件数とその理由）
- タイトル最有力案
- 公開後の記事URL
- 本文文字数
- 参照した一次情報ファイル
- 事実確認できなかった点
- commit hash（該当なしの場合はその旨）
- SNS（X）投稿下書き（記事を公開できた場合のみ、末尾に追記する）
