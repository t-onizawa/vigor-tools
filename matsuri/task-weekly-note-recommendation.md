# VIGOR MATSURI — 週次「今週のおすすめ祭り」note記事タスク

Codex Scheduled Task用の実行指示書。Codex側のプロンプトは本ファイルを
読み込んで指示通りに実行する形にする。基準・運用ルールの変更は本ファイル
のみを更新し、Codex側のプロンプト自体は書き換えない。

---

VIGOR MATSURIの「今週のおすすめ祭り」note記事を作成・公開する。

## 目的

開催が近い祭りを1つ選び、短い紹介記事を書き、VIGOR MATSURIの該当
詳細ページへ自然な導線を作る。既存の「週次note下書き」タスク（一人称
エッセイ・その週に起きた活動から選ぶ）とは選定ロジック・文体が異なる
別タスクであり、役割を混同しない。

**このタスクに限り、Founderの明示的な許可によりnoteへの自動公開が
許されている**（AGENTS.md「note自動公開の例外」参照）。他のnote関連
タスクにはこの許可は適用されない。

## 対象祭りの選定ロジック

1. `matsuri/festivals/`配下の全`data.js`を確認する
2. 以下をすべて満たす祭りを候補とする：
   - `eventStatus`が`confirmed`または`scheduled_pending_official`
   - 2026年の開催日が実行日から30日以内
3. 以下は候補から除外する：
   - 過去に本タスクが紹介済みの祭り（note上の公開済み記事一覧を
     確認し、既出のslugを除外する）
   - note上で既に個人エッセイ等、独立した記事で大きく扱われている祭り
4. 候補が複数ある場合は、開催日が最も近いものを選ぶ
5. 候補が0件の場合は、記事を作らず完了報告のみ行う（該当祭りなしの
   旨と、次回以降の候補になりそうな祭りがあればメモを残す）

## 実行内容

1. 選んだ祭りと選定理由を短く示す
2. `matsuri/festivals/{slug}/data.js`と`matsuri/research/{slug}.md`の
   一次情報を確認する
3. タイトル案を3案作り、最有力を1つ選ぶ
4. 800〜1,200字程度の紹介文を書く（何が見どころか、いつ・どこで
   開催か、行く前に確認したいことを簡潔に伝える。既存の週次noteタスク
   のような一人称の起承転結エッセイにはしない）
5. ハッシュタグ候補を3〜5個付ける
6. 件数・日付・固有名詞は`data.js`・`research/{slug}.md`で確認できた
   ものだけを使う。確認できないことは推測で埋めない
7. 記事末尾に、VIGOR MATSURIの該当詳細ページへのリンクを1つだけ置く。
   URLは以下の形式でUTMを付ける（`{slug}`は対象祭りのslugに置き換える）：
   `https://vigorlab.net/matsuri/festivals/{slug}/?utm_source=note&utm_medium=article&utm_campaign=weekly-pick-{slug}`
8. noteのログイン済みブラウザセッションを使い、採用タイトル・本文・
   ハッシュタグをnoteの新規記事編集画面へ入力し、**公開する**（下書き
   保存で止めず、公開操作まで実行する）
9. 公開後の記事URLを取得し、完了報告に記載する

## 毎回、作業開始時に必ず確認すること

- `NoteStyleGuide.md`（リポジトリルート）
- note上の公開済み記事・下書き一覧（重複確認）
- 対象祭りの`data.js`・`research/{slug}.md`

## 文体規約（NoteStyleGuide.mdに従う。特に以下を厳守）

- です・ます調で統一する
- 一人称「僕」は要所だけに使う
- 短い段落と多めの改行で読みやすくする
- 煽らない、成功や魅力を誇張しない
- 確認できた数字・日付・固有名詞を入れる。確認できないことは書かない
- 読者が行く前に確認したいことを1つ、具体的に入れる

## リポジトリ内の保存規約

このタスクはリポジトリへの下書きファイルを作成しない（note上で直接
公開まで完結するため）。リポジトリへの変更は発生しない（下記の
SNS投稿下書きは完了報告内のテキストとして出力するのみで、これも
リポジトリへの変更にはあたらない）。

## SNS（X）投稿下書き（2026-09-16追加）

**今回の実行で記事を公開できなかった場合（候補0件の場合）は、この節
自体を出力しない。** 無理に文面を作らない。

記事を公開できた場合のみ、完了報告の一番最後に、以下の形式でX投稿用
の下書きをそのまま追記する（Founderがコピペしてそのまま手動投稿する
運用のため、完成した投稿文としてそのまま使える状態で出力すること）。

```
【今週のおすすめ祭り】
「{祭り名}」を紹介する記事を公開しました。

{2026年の開催日} {開催地（都道府県・市区町村）}
{公開後のnote記事URL}

#祭り #山車 #神輿
```

ルール：

- リンクはnote記事のURLのみを置く（VIGOR MATSURIの詳細ページ
  リンクは記事本文側に既にあるため、X投稿では二重に貼らない）
- note記事URLにUTMパラメータは付けない（note.com側の解析で活用
  できる保証がなく、リンクが煩雑になるだけのため）
- 開催日・開催地は`data.js`で確認できた値をそのまま使う（推測しない）
- この下書きはコピペしてそのまま使える完成形として出力し、
  「以下のような文面はいかがでしょうか」のような前置きは付けない

## 禁止事項

- 一人称エッセイ形式への逸脱（それは既存の週次noteタスクの役割）
- 過去に紹介済みの祭りを再度紹介すること
- 一次情報にない数字・日付・固有名詞の記載
- force push、`git reset --hard`、履歴の書き換え
- 関係のないファイルのcommit・push

## 完了報告に必ず含めること

- 選んだ祭りと選定理由（該当祭りなしの場合はその旨と次回候補メモ）
- タイトル最有力案
- 公開後の記事URL
- 本文文字数
- 参照した一次情報ファイル
- 事実確認できなかった点
- commit hash（該当なしの場合はその旨）
- SNS（X）投稿下書き（記事を公開できた場合のみ、末尾に追記する）
