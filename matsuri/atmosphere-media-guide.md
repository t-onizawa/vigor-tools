# VIGOR MATSURI — atmosphereMedia 調査・運用ガイド（30件展開版）

```
Version: 1.1
Created: 2026-07-28
Scope: constantInfo.atmosphereMedia の調査・採用・データ入力に関する
       運用ルールを1箇所に集約する。データ構造そのものの定義は
       schema-design.md 設計原則#6を参照（本書は運用ガイド）。
       7節はconstantInfo.backgroundImage（設計原則#12）の運用ルールも
       扱う。
```

石岡のおまつりでの検証（代表動画1件＋補助動画候補3件を実際に調査し、
1件を採用・2件を不採用とした事例）を踏まえ、30件展開時に毎回同じ
基準で判断できるよう、調査ルールを1箇所にまとめる。

---

## 0. 大前提：動画は「確認できた祭りだけを強化する要素」である

**「動画がない」は不足でも欠陥でもない。** VIGOR MATSURIの核となる
情報（開催日・開催地・特徴・アクセス・地図・お囃子・出典）は動画が
なくても完全に成立する設計になっている。動画は、それらの核となる
情報が確認できた上で、**運良く条件を満たす動画も見つかった場合にだけ
追加する「上乗せの体験」**であり、必須項目では一切ない。

このため、30件展開時に「動画が見つからない祭りが多数出る」ことは
想定内であり、失敗でも手抜きでもない。**動画探しに時間をかけすぎて、
一言見どころ・特徴・アクセスなど核となる情報の調査品質を落とすこと
の方が問題である。** 動画調査に時間制限の目安を設けてもよい
（例：1祭りあたり数分〜十数分程度で見つからなければ次に進む）。

---

## 1. atmosphereMediaの入力ルール

```
constantInfo.atmosphereMedia: [
  { ... },  // 0番目 = 代表動画
  { ... },  // 1番目 = 補助動画
  { ... }   // 2番目 = 補助動画
]
```

- **配列順が表示優先順位そのもの。** `priority`のような独立した
  順序フィールドは追加しない（二重管理を避けるため）
- **0番目＝代表動画。** ページ読み込み時に即座にYouTube公式
  プレーヤーで埋め込まれ、ヒーロー的に大きく表示される
- **1〜2番目＝補助動画。** 静的サムネイル＋再生アイコンのみ表示され、
  クリックした時点でiframeに展開される（2列グリッド）
- **最大3件（代表1＋補助2）。** 4件目以降は対応しない
- 補助動画の枠が1つしか埋まらない、あるいはまったく埋まらない
  （代表動画のみ、または空配列）状態は正常であり、**無理に3件へ
  埋める必要はない**（2節参照）

---

## 2. 動画採用基準

すべての候補について、以下を**実際にYouTube動画ページを開いて**
確認する。**検索結果のタイトル・概要文（スニペット）だけでの採用は
一切しない。** 過去に検索エンジンの要約が投稿元を誤って紐づけた
事例が実際に発生している（`research/ishioka-omatsuri.md`参照）。

### 必須確認項目（すべて満たすこと）

1. **投稿者・チャンネル名を、動画ページ上で直接確認する**
   （チャンネル名・登録者数・確認済みバッジの有無を見る）
2. **公式性、または十分な内容品質が判断できる**
   （4節「公式性確認の手順」参照）
3. **実際にその祭りの映像が映っていることを確認する**
   （説明文・サムネイル・可能なら本編の一部を確認する）
4. **代表動画と役割が重複しないことを確認する**（3節参照）

### 代表動画（0番目）の選定基準

- 「祭り全体の雰囲気」が最も伝わるものを優先する
- 掲載優先順位（下記）の中で最も確度が高いものを選ぶ
- 長さは5分前後の総集編・ダイジェスト形式が適している

### 補助動画（1〜2番目）の選定基準

代表動画と**異なる視点**を提供できるものを優先する。視点の例：

```
- 昼の様子 ／ 夜の様子
- 山車・神輿・踊りそのものにフォーカスした場面
- 観客・見物客の視点
- 運行・巡行風景
- 別の日程（初日／最終日等）・別のエリア
```

**「別視点である」ことと「品質が高い」ことは、どちらも満たして
初めて採用理由になる。** 視点が違うだけでは不十分（4節・5節も参照）。

### 掲載優先順位（発信元の確からしさ）

```
1. 祭り公式（実行委員会・保存会等）
2. 自治体・観光協会
3. 地元メディア（新聞・テレビ・地域専門チャンネル等）
4. 内容品質が確認できる個人投稿
```

数を増やすための優先順位ではなく、**同水準の候補が複数ある場合に
どちらを選ぶか**の判断材料として使う。

## 3. 不採用基準

以下のいずれかに該当する場合は採用しない。**品質が高くても、
入口用途（短時間で雰囲気をつかむ）に合わなければ採用しない。**

```
- 祭り名だけが一致する、内容不明の動画
- 投稿者・チャンネルが動画ページ上で確認できない
- AI生成・転載の疑いがある
- 観光PRのみで、実際の祭りの映像が映っていない
- 現在の祭りの実態と大きく異なる可能性がある古い映像
  （即不採用ではないが、publishedYearを明示し年度差を注記する）
- 代表動画（またはすでに採用した補助動画）と役割が重複する
- 長尺・詳細記録系の動画
  （目安：10分を大きく超え、かつ内容が一場面の総合ダイジェストで
  はなく通し記録に近いもの。石岡の調査では20分・48分の候補を
  この理由で不採用とした）
```

**「動画枠を必ず埋める」という発想を持たない。** 補助動画の候補が
上記いずれかに該当する場合、無理に採用せず、その枠は空けたまま
次の祭りの調査に進む。

---

## 4. 公式性確認の手順

1. 検索で候補を見つけたら、**必ず実際の動画ページ（`youtube.com/watch?v=...`）を開く**
2. 動画ページ上で以下を目視確認する
   - チャンネル名・確認済みバッジ（青いチェックマーク）の有無
   - チャンネル登録者数
   - 投稿日（何年何月頃か）
   - 動画の長さ
   - 視聴回数
   - 説明文（実際に何が映っているかの記述）
3. 上記が動画ページ上で直接確認できた場合のみ、`publisher`・
   `publisherType`を確定させる
4. **検索結果の要約・スニペットのみに基づいて`publisher`を
   記入してはならない。** 直接確認できない場合は、その候補を
   `atmosphereMedia`に追加せず保留する

`publisherType`の対応目安：

```
official       祭り公式（実行委員会・保存会等）
government     自治体
tourism        観光協会
local_media    地元新聞・地域専門メディア・地域専門チャンネル
individual     上記に当てはまらない個人投稿
```

全国紙・キー局等の確認済み公式チャンネル（例：朝日新聞）は
`local_media`より確度が高い発信元として扱ってよい（`official`と
`government`の中間に相当する信頼度と捉え、掲載優先順位上は
`government`と同格かそれ以上に扱う）。

## 5. 動画が見つからない場合の扱い

```
constantInfo.atmosphereMedia: []
```

**これは正常な状態であり、不足ではない。** 以下を徹底する。

- 見つからない場合に、基準を緩めてまで候補を採用しない
- 見つからない場合に、調査時間を過剰に延長しない
  （目安時間を超えたら次の祭りへ進む）
- 空配列でも詳細ページは既存の設計どおり自然に成立する
  （動画セクション自体が非表示になり、前後のセクションの余白が
  崩れないことは実装済み・確認済み）
- 動画が見つからない祭りが30件中の多数を占めても、それ自体は
  問題として扱わない。むしろ「一言見どころ」「特徴」「開催情報」
  など、動画に頼らず成立する核の情報の質を上げる方向に注力する

## 6. researchファイルへの記録項目

各祭りのresearchファイル（`research/{slug}.md`）に、動画調査の
結果を以下の形式で記録する（石岡の記録を実例として参照）。

```
- 確認した候補一覧（タイトル・URL・投稿チャンネル・登録者数・
  動画の長さ・視聴回数・判定〔採用／不採用〕）
- 採用した動画について
  - 投稿者確認の詳細（チャンネル名・確認済みバッジ・登録者数）
  - 公式性の位置づけ（掲載優先順位のどこに当たるか）
  - 動画内容の要約（何が映っているか）
  - publishedYearの根拠
  - 代表動画（または他の採用済み動画）との役割分担
- 不採用にした候補について
  - 不採用理由（3節のどの基準に該当するか）
- 候補が1件も見つからなかった場合
  - 「候補調査を行ったが、採用基準を満たす動画は見つからなかった」
    と明記する（調査自体を省略していないことの記録として残す）
```

## 7. 背景素材（constantInfo.backgroundImage）の採用基準（2026-07-29改訂）

**背景素材（一覧カード背景・詳細ページヒーロー）は`atmosphereMedia`とは
独立したフィールド`constantInfo.backgroundImage`として管理する。**
石岡・熊谷うちわ祭・八王子まつりで実際に候補調査を行った結果、
「動画として優れている（公式性・尺）」ことと「サムネイルが背景素材
として優れている（文字がなく主役が写る）」ことは一致しないケースが
多いと判明したためである（詳細はschema-design.md 設計原則#12）。

**したがって、backgroundImageの採用基準はatmosphereMediaの採用基準
（1〜4節：publisherType・動画の尺等）を一切引き継がない。** 別の
動画・別の投稿者から選んでよく、atmosphereMediaに採用されなかった
（尺が短すぎる／長すぎる等の理由で不採用になった）動画のサムネイルを
backgroundImageとして採用することも問題ない。

### 必須条件（すべて満たすこと）

```
1. 山車・神輿・踊りなど、その祭りの主役となる要素が画像から
   視覚的に判別できる
2. サムネイルに大きな文字・タイトルロゴが乗っておらず、現地の
   雰囲気がそのまま見える（小さなチャンネルロゴ程度は許容するが、
   フレームの大部分を覆う装飾文字・バナーは不可）
3. 現地で撮影された実写である（イラスト・ロゴ・説明用の図解画像
   ではない）
```

**明示的に不採用理由にしないもの：**

```
- publisherTypeがindividual（個人）であること
  （atmosphereMediaでは掲載優先順位の判断材料だが、backgroundImageは
  画像の質のみで判断する）
- 動画自体の長さ（36秒の短い動画・100分超の長時間記録のどちらも、
  静止画1枚を参照する用途では問題にならない）
```

**ただし投稿者確認の手順（4節）は同様に適用する。** 検索結果の要約
だけで判断せず、必ず動画ページを直接開いて投稿者・内容を確認する。
AI生成・転載疑いのある動画、祭りと無関係な動画は当然除外する。

### 素材がない場合の扱い

**上記を満たす候補がない場合、無理に背景を設定しない。** `backgroundImage`
を`null`のままにする。atmosphereMedia自体は動画情報として引き続き
詳細ページに表示される（backgroundImageの有無とは独立）。「動画が
あるから背景を付ける」のではなく、「その祭りの空気が一瞬で伝わる
素材が確認できたから背景を付ける」という順序を守る。

### researchファイルへの記録

backgroundImageの候補調査・採用理由は、atmosphereMediaとは別の
候補として research/{slug}.md に記録する（同じ動画を指す場合も
異なる動画を指す場合もあるため、混同しないよう明記する）。

## この文書の使い方

- 30件展開の各祭りで動画候補を調査する際、本書の1〜6節を
  そのままチェックリストとして使う
- スキーマの構造（フィールド定義）を確認したいときは
  `schema-design.md` 設計原則#6を参照する
- 表示・UIの仕様（ギャラリー表示・クリック展開等）を確認したいときは
  `template-design.md` 8-2-1節を参照する
- 石岡のおまつりでの実例（採用1件・不採用2件の判断根拠）は
  `research/ishioka-omatsuri.md`を参照する
